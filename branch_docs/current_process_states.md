# 1. Текущие состояния процесса в Linux


## Основные состояния (`task_struct.state`)


В ядре Linux процесс может находиться не только в базовых состояниях (`RUNNING`, `SLEEPING`, `STOPPED`, `ZOMBIE`), но и во множестве **промежуточных и специализированных состояний**. Эти состояния отражаются в поле `task_struct.state` и `task_struct.exit_state`, а также через дополнительные **флаги** `task_struct.flags`.

1. **TASK\_RUNNING (0x0000)**

   * Поток либо выполняется на CPU, либо стоит в очереди готовых.
   * У него нет блокировок, он доступен планировщику.

2. **TASK\_INTERRUPTIBLE (0x0001)**

   * Поток "спит" в ожидании события (например, завершения I/O).
   * Может быть прерван сигналом → возвращается в `TASK_RUNNING`.

3. **TASK\_UNINTERRUPTIBLE (0x0002)**

   * Поток ожидает без возможности прерывания сигналом.
   * Используется при работе с железом или в критичных участках ядра.

4. **TASK\_STOPPED (0x0004)**

   * Процесс остановлен сигналом (`SIGSTOP`, `SIGTSTP`, `SIGTTIN`, `SIGTTOU`).
   * Может быть возобновлён `SIGCONT`.

5. **TASK\_TRACED (0x0008)**

   * Процесс отлаживается через `ptrace()`.
   * Все его действия контролируются отладчиком.

6. **EXIT\_DEAD (0x0010)**

   * Процесс окончательно уничтожен, память и ресурсы освобождены.

7. **EXIT\_ZOMBIE (0x0020)**

   * Процесс завершил работу, но его `task_struct` и PID ещё существуют.
   * Родитель должен вызвать `wait()` для сбора exit-кода.

8. **TASK\_DEAD (0x0040)**

   * Завершён, недоступен планировщику. Используется для финальной очистки.

9. **TASK\_WAKEKILL (0x0080)**

   * Вариант состояния сна, из которого можно пробудить только фатальным сигналом.

10. **TASK\_WAKING (0x0100)**

    * Промежуточное состояние при переводе процесса из сна в `TASK_RUNNING`.
    * Используется для синхронизации между процессорами.

11. **TASK\_PARKED (0x0200)**

    * Используется для *kthread* (kernel thread). Поток "припаркован", но не завершён.

12. **TASK\_NOLOAD (0x0400)**

    * Поток не учитывается в статистике планировщика. Применяется для служебных потоков ядра.

13. **TASK\_NEW (0x0800)**

    * Новый процесс, ещё не запущенный планировщиком.

14. **TASK\_IDLE (0x1000)**

    * Специальное состояние для `idle`-потоков, когда CPU ничего не делает.

---

## Состояния завершения (`exit_state`)

* **EXIT\_ZOMBIE (0x0020)** — процесс "зомби".
* **EXIT\_DEAD (0x0010)** — финальное завершение.

---

## Важные флаги (`task_struct.flags`)

Эти флаги дополняют автомат состояний:

* **PF\_KTHREAD** — поток ядра, не имеет пользовательского адресного пространства.
* **PF\_FORKNOEXEC** — процесс был создан, но ещё не вызвал `execve()`.
* **PF\_SUPERPRIV** — процесс получил привилегии суперпользователя.
* **PF\_DUMPCORE** — процесс в процессе дампа core-файла.
* **PF\_SIGNALED** — завершился из-за сигнала.
* **PF\_EXITING** — процесс находится в стадии выхода.
* **PF\_WQ\_WORKER** — поток является рабочим (`workqueue worker`).

---

## Дополнительные под-состояния и флаги

Помимо основных, в Linux могут встречаться промежуточные состояния:

* **TASK\_NEW** — процесс только что создан (`fork`/`clone`) и ещё не запущен.
* **TASK\_IDLE** — процессы, связанные с простоями ядра (idle tasks).
* **TASK\_PARKED** — используется для потоков ядра (kernel threads), когда они временно "отключены".
* **TASK\_DEAD** — фактически равнозначен EXIT\_DEAD, но применяется на разных стадиях освобождения структуры.

## Подробные переходы

### 1) Создание и первый запуск

* `fork()/clone()` → новый поток попадает в **`TASK_NEW`**. После инициализации его ставят в очередь планировщика и он становится **`TASK_RUNNING`** (готов или уже выполняется).
  Ключевые пути кода: выделение `task_struct`, инициализация полей, постановка в rq.

### 2) Переход из выполнения в ожидание (сон)

* Когда поток ждёт событие (I/O, мьютекс), ядро:

  1. выставляет его состояние через `set_current_state(TASK_INTERRUPTIBLE)` или `set_current_state(TASK_UNINTERRUPTIBLE)`,
  2. добавляет в очередь ожидания,
  3. вызывает `schedule()` для переключения.
     В `TASK_INTERRUPTIBLE` пробуждение возможно и сигналом, в `TASK_UNINTERRUPTIBLE` — только «условием» (например, завершением I/O).

### 3) Пробуждение из ожидания

* Пробуждение выполняет `try_to_wake_up(p, mask, flags)`:

  * если маска `mask` совпала с текущим `p->state`, поток переводится в **`TASK_RUNNING`** и ставится на runqueue;
  * между сменой состояния и постановкой на rq на SMP используется промежуточное **`TASK_WAKING`** для защиты от гонок.

### 4) Останов/продолжение

* `SIGSTOP`/`SIGTSTP` переводят в **`TASK_STOPPED`**, где поток не планируется до `SIGCONT`; `SIGCONT` возвращает в **`TASK_RUNNING`**. `ptrace()` вводит **`TASK_TRACED`**, где выполнение контролирует отладчик; `PTRACE_CONT`/detach — обратно в **`TASK_RUNNING`**.

### 5) Завершение жизни

* Поток вызывает `do_exit()` → **`EXIT_ZOMBIE`** (ядро сохраняет код возврата/статистику до сбора родителем).
* Родитель вызывает `wait()` → ресурсные структуры освобождаются → **`EXIT_DEAD/TASK_DEAD`**.

### 6) Специальные и служебные состояния

* **`TASK_PARKED`** — kthread временно «припаркован», не планируется до `kthread_unpark()`.
* **`TASK_NOLOAD`** — исключение из расчётов нагрузки планировщика (служебные потоки).
* **`TASK_IDLE`** — специальный idle-поток на каждом CPU, выбирается только при отсутствии других runnable задач.
